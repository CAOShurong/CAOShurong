## Shurong Cao

I build small command-line tools that answer one question well, and refuse to
answer when the data can't support it.

All of them share the same constraints: **zero runtime dependencies**, standard
library only, tested on Linux, Windows and macOS across Python 3.9–3.13, and
documentation whose figures are generated by running the tool so CI fails when
they drift.

### Tools

| | What it answers | |
| --- | --- | --- |
| **[evalint](https://github.com/CAOShurong/evalint)** | Is my LLM eval set any good? Reliability, items scored against a wrong answer, near-duplicates, and how many test cases you can drop without changing the ranking. | [PyPI](https://pypi.org/project/evalint/) |
| **[willitbreak](https://github.com/CAOShurong/willitbreak)** | Will this dependency upgrade break *my* code? Diffs a package's API between two versions and reports only the breaks that reach your call sites, with line numbers. | [PyPI](https://pypi.org/project/willitbreak/) |
| **[slowimports](https://github.com/CAOShurong/slowimports)** | Why is my Python CLI slow to start, and which imports can I safely make lazy? | [PyPI](https://pypi.org/project/slowimports/) |
| **[jsonxray](https://github.com/CAOShurong/jsonxray)** | What is actually inside this JSONL file, including the records that don't match the rest? Constant memory, any file size. | [PyPI](https://pypi.org/project/jsonxray/) |
| **[termscope](https://github.com/CAOShurong/termscope)** | What is my microcontroller actually sending? A live serial plotter in the terminal, no GUI. | [PyPI](https://pypi.org/project/termscope/) |

### The thing they have in common

Each one exists because the honest answer to a common question was *"nobody
checks that"*.

Every eval framework runs your test cases; none ask whether the test cases are
any good. Every API-diff tool tells you what a library changed; none tell you
whether you used any of it. `-X importtime` tells you what is slow to import;
it does not tell you what you could move into a function.

So the hard part is usually not the measurement — it is knowing when the
measurement does not license a conclusion, and saying so instead of printing a
confident number. `evalint` will refuse to call an item broken on three
systems, because three systems genuinely cannot tell a broken item from an
unlucky one. `willitbreak` will not report a call site whose origin it cannot
prove.

A tool that cries wolf gets uninstalled after the second false alarm, and then
catches nothing at all.
